# Reviewing a model-generated incident briefing

The LangGraph assistant already assembles monitoring readings, normalized log patterns, and runbook passages for a recorded minute. It can request a structured explanation from an external model when an operator explicitly allows data sharing. Streamlit can review the resulting JSON without allowing either the dashboard or FastAPI to request generation.

## Generate a draft separately

From the Codespace, with the original source files and trained artifacts available:

```bash
mkdir -p reports/incident_drafts
umask 077
# Configure OPENAI_API_KEY in the terminal environment; do not store it in Git.
.venv/bin/python scripts/ask_incident.py \
  --as-of "2025-10-25 18:01:00" \
  --question "network timeout latency" \
  --model YOUR_AVAILABLE_MODEL \
  --allow-external-data \
  > reports/incident_drafts/network-timeout-1801.json
```

`YOUR_AVAILABLE_MODEL` must be replaced with a model supported by the configured API account. The command requires an API key and the explicit `--allow-external-data` flag. It sends the question, up to ten historical monitoring values with reference medians, twelve normalized log patterns, and three runbook passages to the model API. Normalization masks identifiers in known log patterns but is not a guarantee that every sensitive value is removed. **Do not run this command unless those records are approved for external processing.** Model requests may incur charges. The request uses `store=False`, but the provider's applicable retention and processing policies still matter.

The output file contains evidence and potentially sensitive operational details. It remains under ignored `reports/`, not in Git or Docker images. If the remote request fails, the command exits with an error; do not import a partial or empty file. The model output is a draft, not a confirmed diagnosis or an authorization to execute runbook procedures.

## Import and review in Streamlit

1. Run the existing FastAPI and Streamlit services locally, or through the private Codespaces ports. Select the same historical minute in **Incident replay**.
2. Enter the same investigation question and select **Assemble evidence briefing**.
3. Under **Model-generated explanation**, upload the JSON file from the command above and select **Check draft against recorded evidence**.
4. Review the summary, observations, possible explanations, suggested checks, uncertainty, and source coordinates.

Streamlit sends the uploaded JSON only to the configured local FastAPI service. `POST /api/v1/investigations/check-draft` rebuilds the original investigation from the saved artifacts; it does **not** call any external model. It checks the draft's timestamp, question, recorded values, output fields, and evidence IDs, then reconstructs source paths, rows, and line numbers from the local evidence rather than trusting paths in the uploaded file. Imported files are limited to 64 KiB. The dashboard does not save the upload.

A valid citation ID proves only that the referenced record exists in this investigation. It does **not** prove the model's wording is supported, that its stated hypothesis is correct, or that the JSON file was actually generated by a model. The original `root_cause` and `resolution` fields remain unset. The app labels the imported result `citation_ids_checked`, and human review remains necessary.

## Testing

Run the local validation and API contract checks:

```bash
.venv/bin/python tests/test_incident_drafts.py
.venv/bin/python tests/test_incident_draft_api.py
```

The integration suite loads the saved anomaly, log, and FAISS artifacts and must run in Codespaces:

```bash
.venv/bin/python tests/test_incident_draft_integration.py
```

The integration suite uses locally constructed, source-backed cases and makes **no remote API request**. Separately, one live `gpt-5.4-mini` request for `2025-10-25 18:01:00` returned a structured explanation that passed the CLI checks, and its JSON was imported and displayed in Streamlit. That verifies the demonstrated integration, not the accuracy of explanations for other incidents. The model's suggestions and interpretations still need human review.

The API and dashboard still have no authentication and are intended only for local or private access. This feature does not turn historical CSV replay into a live monitoring feed.
